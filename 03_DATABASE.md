# DATABASE.md — Supabase PostgreSQL Schema

## 1. Important security rule

Do NOT create a plaintext `password` column for application authentication.

Supabase Auth stores passwords securely in `auth.users`.

The public profile table should store application data only.

## 2. Tables

### profiles

```sql
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  username text unique not null,
  email text,
  role text not null default 'USER' check (role in ('ADMIN','USER')),
  status text not null default 'ACTIVE' check (status in ('ACTIVE','INACTIVE')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### video_categories

```sql
create table public.video_categories (
  id bigint generated by default as identity primary key,
  name text not null unique,
  slug text not null unique,
  description text,
  status text not null default 'ACTIVE' check (status in ('ACTIVE','INACTIVE')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### videos

```sql
create table public.videos (
  id bigint generated by default as identity primary key,
  title text not null,
  slug text unique,
  description text,
  category_id bigint references public.video_categories(id) on delete restrict,
  video_url text,
  video_path text,
  thumbnail_url text,
  thumbnail_path text,
  views bigint not null default 0 check (views >= 0),
  file_size bigint not null default 0 check (file_size >= 0),
  duration_seconds integer,
  status text not null default 'ACTIVE'
    check (status in ('ACTIVE','INACTIVE','DRAFT')),
  created_by uuid references public.profiles(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### video_views

Use one row per view event.

```sql
create table public.video_views (
  id bigint generated by default as identity primary key,
  video_id bigint not null references public.videos(id) on delete cascade,
  viewer_id uuid references auth.users(id) on delete set null,
  viewed_at timestamptz not null default now()
);
```

## 3. Indexes

```sql
create index idx_videos_category on public.videos(category_id);
create index idx_videos_status on public.videos(status);
create index idx_videos_views on public.videos(views desc);
create index idx_videos_created_at on public.videos(created_at desc);
create index idx_video_views_video_id on public.video_views(video_id);
create index idx_video_views_viewed_at on public.video_views(viewed_at);
```

## 4. Trigger: create profile after registration

Use a secure PostgreSQL trigger to create profile data after a new auth user is created.

Do not allow the browser to assign ADMIN role during registration.

Default role must always be USER.

## 5. Sample development accounts

Requested development accounts:

### ADMIN

```text
username: admin1
email: admin1@gmail.com
password: 123456
role: ADMIN
```

### USER

```text
username: user1
email: user1@gmail.com
password: 123456
role: USER
```

These credentials are for local/demo setup only.

Supabase Auth should create the users. Then update the corresponding profile role for `admin1` through a trusted/admin setup process.

Never expose a Supabase `service_role` key in frontend JavaScript.

For any real deployment, replace these passwords with strong unique passwords.

## 6. Storage

Recommended buckets:

```text
videos
thumbnails
```

Suggested object paths:

```text
videos/{user_id}/{timestamp}-{safe-file-name}
thumbnails/{user_id}/{timestamp}-{safe-file-name}
```

Do not use user-provided filenames directly as trusted paths.

## 7. Dashboard queries

Total videos:

```sql
select count(*)
from public.videos
where status = 'ACTIVE';
```

Total views:

```sql
select coalesce(sum(views), 0)
from public.videos
where status = 'ACTIVE';
```

Top 10:

```sql
select id, title, views
from public.videos
where status = 'ACTIVE'
order by views desc
limit 10;
```

Views by day:

```sql
select
  date_trunc('day', viewed_at) as period,
  count(*) as views
from public.video_views
group by 1
order by 1;
```

Storage:

```sql
select coalesce(sum(file_size), 0)
from public.videos
where status = 'ACTIVE';
```

For very large datasets, use SQL functions/materialized summaries rather than downloading all rows to the browser.
